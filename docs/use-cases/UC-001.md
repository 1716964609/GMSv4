# UC-001 — Translate Text

**Status:** Draft
**Version:** 0.1

## 1. Overview

**Primary Actor:** Operator

**Goal:**
Translate Original Text using DeepL and GPT while applying
terminology from the currently Uploaded Glossary.

**Linked Requirements:**
FR-001, FR-002, FR-003, FR-004, FR-005, FR-006, FR-007,
C-002, C-003, C-004

## 2. Preconditions

- The Operator can access the application through a browser.
- No authentication is required.
- The Operator can specify source and target languages.

## 3. Trigger

The Operator clicks the Submit button to request translation.

## 4. Main Success Scenario

1. The Operator enters Original Text into the browser text box.

2. The Operator specifies the source and target languages.

3. The Operator optionally uploads a JSON glossary file
   containing Glossary Entries.

4. The application enables the Submit button when
   Original Text is not empty.

5. The Operator clicks Submit.

6. The application sends the Original Text, selected
   language pair, and applicable entries from the
   current Uploaded Glossary to DeepL.

7. DeepL produces the Intermediate Translation.

8. The application provides the following to GPT:
   - Original Text
   - Intermediate Translation
   - Applicable entries from the Uploaded Glossary

9. GPT performs translation post-editing to improve
   translation quality while following the specified
   target terminology.

10. GPT produces the Final Translation.

11. The application displays the Final Translation
    in the browser.

12. The application provides a Download button
    for saving the Final Translation as a TXT file.

13. After translation, the application appends
    the current Uploaded Glossary Entries to the
    persistent Glossary database.

## 5. Alternative Flows

### A1 — Empty Original Text

**Condition:** Original Text is empty.

1. The Submit button remains disabled.
2. The Operator cannot initiate translation.

### A2 — No Glossary Uploaded

**Condition:** The Operator does not upload a glossary.

1. The application proceeds with translation
   without glossary terminology.
2. DeepL generates the Intermediate Translation.
3. GPT performs post-editing.
4. The Final Translation is returned to the Operator.
5. No Glossary Entries are appended to the database.

### A3 — Download Final Translation

**Condition:** The Final Translation is displayed.

1. The Operator clicks Download.
2. The application downloads the Final Translation
   as a TXT file.

## 6. Postconditions

### Successful Translation

- A Final Translation is available in the browser.
- The Final Translation can be downloaded as a TXT file.
- Uploaded Glossary Entries, if provided, are appended
  to the persistent Glossary database.
- Previously stored Glossary Entries remain unchanged.
- Original Text, Intermediate Translation, and
  Final Translation are not stored in the application database.

## 7. Business Rules

**BR-001 — Current Glossary Only**

Only Glossary Entries from the current upload
are used for translation.

Previously stored Glossary Entries are not used
to influence the current translation.

**BR-002 — Sequential Translation**

The Intermediate Translation must be produced
by DeepL before GPT performs post-editing.

**BR-003 — Terminology Alignment**

Both translation stages use applicable terminology
from the current Uploaded Glossary.

GPT must be instructed to follow the specified
target terminology.

**BR-004 — Glossary Accumulation**

Uploaded Glossary Entries are appended to the
persistent Glossary after translation.

Existing entries are not deleted or replaced.

**BR-005 — Transient Translation Data**

Original Text, Intermediate Translation,
Final Translation, and Translation Requests
must not be stored in the application database.
